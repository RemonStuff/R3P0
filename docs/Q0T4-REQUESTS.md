# Requests for Q0T4

Things R3P0 needs from Q0T4 that aren't in Q0T4's plan (`main` @ `ef19933`) yet. R3P0 never changes Q0T4. Remon takes these to the Q0T4 repo. Each request says what R3P0 does until it's resolved.

| # | Request | Why | Until then, R3P0… |
|---|---|---|---|
| R1 | **Write PLAN §9** (credits, cycles, pool, reserve, `reserveMode`, ledger, public API). PLAN.md refers to §9, §9.1, §9.3, §9.6 and §9.7, but none of them exist. | R3P0 can't match an API that isn't specified. | Builds against the proposal in [Q0T4-API-CONTRACT.md](Q0T4-API-CONTRACT.md). |
| R2 | **`sendRequest` takes a model *reference* `{ vendor, id }`**, not a `LanguageModelChat` object. Q0T4 calls `vscode.lm.selectChatModels({ vendor, id })` itself. | `LanguageModelChat` objects belong to the extension that selected them. If Q0T4 called `sendRequest` on R3P0's object, the request would run (and ask for consent) as R3P0, which defeats "R3P0 never calls a model". | Sends `{ vendor, id }`. |
| R3 | **Messages are plain JSON** `{ role: "user" \| "assistant", content: string }`. | Keeps vscode classes from crossing the extension boundary, and makes the API testable. | Sends plain JSON. |
| R4 | **`getStatus({ subjects })` returns an entry for every requested subject**, including ones with zero usage (with the default budget or pool share), plus `reserveMode`, `unit`, `pool.reserve` and monthly `pace`. | Tabs and the Overview must show budgets for repos that haven't been used yet. | Shows "No budget info" for missing subjects. |
| R5 | **Borrow approval through the API:** `canSpend` returns `needs-borrow`, and `sendRequest(..., { approveBorrow: true })` lets that request draw from the reserve. Without approval in `"ask"` mode, `sendRequest` rejects with `code: "borrow-required"`. | Requirement: R3P0 shows the approve-borrow button. | Implements exactly this against the fake. |
| R6 | **Structured errors:** `sendRequest` rejects before the first chunk with `{ code, decision? }` (`refused`, `borrow-required`, `model-not-found`, `no-permissions`, `blocked`, `unknown`). A budget cut-off mid-stream is **not** a rejection: `text` ends and `result.stopped === "budget"`. | R3P0 needs to tell "budget spent" (disable input) apart from "model failed" (retry). | Maps unknown codes to "Failed". |
| R7 | *(Nice to have)* **`subjectForFolder(uri: string): Promise<string \| undefined>`** in the API, using Q0T4's own resolver. | A single source of truth for repo identity. | Uses its own copy of the issue 27 rules. When the helper exists, R3P0 prefers it and a contract test checks that both agree. |
| R8 | **Publish the repo-identifier case table** from issue 27 as a data file (for example `test/contract/repo-identity-cases.json`), with a version. | R3P0's contract test can copy it verbatim and notice when it changes. | Copies the cases from the issue 27 text, recording the Q0T4 commit. |
| R9 | **Concurrent `sendRequest` calls on the same subject:** define what happens (serialise, or reserve the estimate before streaming). | Two R3P0 tabs can share a subject (two clones), and `@q0t4` can run at the same time, so both may pass the pre-check. | Allows only one request in flight per tab. |
| R10 | **Keep the default (workspace) `extensionKind`** and document that API consumers must run in the same extension host. | `exports` are only visible within one extension host, which matters for remote development (SSH, WSL, Codespaces). | Documents the same constraint. |
| R11 | **`onDidChangeUsage` also fires when budgets change** (settings, a pool re-split, a new cycle, a reset, a `/sync` correction), not only after requests. | Tab headers would go stale. | Also refreshes every 60 s while visible (fallback). |
| R12 | **Ledger attribution:** record `options.source` (`"r3p0"`) in the ledger entry. | Lets `/status` show where usage came from. | Always sends `source: "r3p0"`. |
| R13 | **Cancellation token is used structurally** (`isCancellationRequested`, `onCancellationRequested`). | R3P0's core passes a structural token. | Its adapter passes a real `vscode.CancellationToken` anyway. |
| R14 | **`context-too-long`:** Q0T4 trims or refuses with a clear code when the messages exceed `maxInputTokens`. | R3P0 only estimates (`chars / 4`). It can't count exactly without calling the model. | Trims conservatively and shows any refusal. |
